## 2026-11-25 (evening) — session: window chrome fixes (v1.16.0)

- Four owner-requested fixes (audit `docs/audits/2026-11-25-window-chrome-fixes.md`, spec `docs/specs/window-chrome-fixes.md`, DECISIONS §58):
- **The Manager window can be moved.** It was genuinely locked: both windows are frameless and nothing ever defined a drag region. The title bar is now the Wails drag region (`--wails-draggable`), with the Minimize/Maximize/Close buttons excluded so their clicks can never turn into drags. The popup stays auto-centered by design — it re-centers at every quick-search show.
- **The document editor's inline panel is quieter:** the bold "Replace document" label and the dim "Loaded/Edited" chip are gone (owner request); the row keeps only the right-aligned "Full editor" button.
- **The "⋯ More actions" menu overlays instead of pushing the page.** It now floats in a fixed-position layer anchored to its button — above it when there is no room below (the usual case at the editor footers) — instead of growing the editor's scroll area and leaving dead space. Choosing an item, clicking outside, pressing Esc, or scrolling closes it. Works identically inside the full-editor modals.
- **Rounded window edges on Windows 11:** both windows now ask the OS explicitly for the system rounded corners (DWM corner preference). Windows 10 keeps its native square look — that OS has no rounded-corner support for solid windows.
- Tests: 207 → 212 (menu portal + document-panel regression), tsc, token lint, AA contrast green; real-browser harness round with four screenshots (`docs/assets/2026-11-25-window-chrome-1..4-*.png`) pinning the overlay behavior (scroll area unchanged on open, menu above the trigger). Window dragging and the DWM corners are Windows-only behaviors — CI builds and tests them on windows-latest; the owner's machine is the final smoke test.
- Version 1.16.0 (five places: `app.go`, the NSIS installer, `winres/info.json`, `types.ts`, tag).

## 2026-11-25 (later) — session: basic text formatting for the document editors (v1.15.0)

- New feature (owner request: "I want the editor to have some basic text editing options, like Bold Italic Emoji (full pack), Alignment etc (just the basic ones)"; audit `docs/audits/2026-11-25-rich-text-document-editor.md`, spec `docs/specs/rich-text-document-editor.md`, DECISIONS §57): both document editors — the inline panel and the full modal — are now dual-mode with a **Plain text / Rich text** switch. Rich mode is a WYSIWYG editor with the basic toolbar: **Bold, Italic, Underline, Strikethrough, Align left/center/right, bulleted + numbered lists, the full emoji pack (1,914 emojis, 9 categories, search, recents), Undo, Redo, Clear formatting**.
- The mode is stored in the document itself (`<!--clavis-rich-->` + HTML), so every existing plain document stays byte-identical until you flip the switch — and plain mode remains exactly the byte-exact editor of v1.14.0. Plain → rich converts losslessly (one paragraph per line); rich → plain asks "Remove formatting?" when formatting would be lost.
- Saving sanitizes the HTML (an allowlist — scripts and event handlers can never reach the vault), refuses an empty draft, and the live stats count the plain text (the bytes a copy produces), matching the backend.
- **Copying:** "Copy document" everywhere stays the privacy-guarded backend copy and hands back clean plain text for rich documents too (the backend strips the markup). The full editor adds **"Copy formatted"** — styled text (`text/html` + `text/plain`) on the standard clipboard, so pasting into Word/Gmail/Slack keeps the styling; the hint says which copy keeps what.
- Item values and notes deliberately stay plain (masked secrets, dotenv pairing and note search would break — see the audit). The markdown export/import round-trip is untouched.
- Dev harness gained a FAKE rich document group; five screenshots in `docs/assets/2026-11-25-harness-rich-1..5-*.png` verify in a real browser, and "Copy formatted" was verified against a real Chromium clipboard (both flavors byte-checked). Go changes (`DocumentPlainText` for copies + stats, a `docRich` state flag) are pinned by `internal/store/richdoc_test.go` and run in CI.
- Tests: 159 → 207 (+48: format layer, editor, picker, dual-mode editors, carry), all green; tsc, token lint and AA contrast gates pass. One new frontend dependency: `unicode-emoji-json` (MIT, the full emoji dataset, lazy-loaded, offline).
- Version 1.15.0 (five places: `app.go`, `clavis.nsi`, `winres/info.json`, `types.ts`, tag).

## 2026-11-25 — session: full-modal editor for whole-document groups (v1.14.0)

- New feature (owner report with a screenshot marking the spot on the "Replace document" row: "I want a button where I drawn a black/yellow one, to edit the content of each item in a full modal editor"; audit `docs/audits/2026-11-25-document-full-editor.md`, spec `docs/specs/document-full-editor.md`, DECISIONS §56): a whole-document group's stored file now has the big editor too — the item editor got its full modal in v1.12.0 and row launch buttons in v1.13.0, but a document group's content was still confined to the tight 12-row inline editor.
- The "Full editor" button sits exactly where the owner marked it (right end of the "Replace document" row, same Maximize2 glyph as every other launch point). Clicking it moves the whole editing session into a ~900px modal: the inline draft — unsaved edits included — carries over, a 24-row mono editor with live draft stats (rune count / line count, the backend's rule) opens, and saving writes byte-exact through the unchanged `setGroupDocument`, toasts, and closes.
- The inline session closes when the full one opens, so a stale inline draft can never sit behind the modal and overwrite a save made there. The dirty-close guard ("Discard changes?" — Keep editing / Discard) matches the item full editor's exactly. The modal is owned by the manager (like the Manage items and item full editor modals) because a document save bumps the group's `updatedAt`, which re-keys the group editor behind it.
- Read-only hides the button (same as the "Edit document" pencil); the backend is untouched — documents still never travel in the state snapshot.
- Dev harness (unshipped dev tool) gained a FAKE document group and `getGroupDocument`/`setGroupDocument` handlers, enabling real-browser verification: four screenshots in `docs/assets/2026-11-25-harness-11..14-*.png`.
- Tests: 148 → 159 (+11: the modal's fetch/seed/save/empty/guard/stats paths, the panel hand-off carrying an unsaved inline draft with the group id, the manager-level open+save), all green; tsc, token lint and AA contrast gates pass. Go untouched.
- Version 1.14.0 (five places: `app.go`, `clavis.nsi`, `winres/info.json`, `types.ts`, tag).

## 2026-11-24 — session: self-update download resilience (v1.12.1)

- Bug fix (owner report: in-app update to 1.12.0 failed with `net/http: TLS handshake timeout` on the GitHub asset CDN): the updater now survives censored/throttled networks. Root cause: Go's net/http ignores the Windows system proxy (the setting every VPN client writes); on the owner's network the CDN host's TLS handshake starves while `api.github.com`/`github.com` answer fine (audit: `docs/audits/2026-11-24-self-update-download-failure.md`, spec: `docs/specs/self-update-download-resilience.md`, DECISIONS §54).
- Four layers: proxy-aware transports (env proxy → Windows system proxy → direct; a direct fallback transport runs when the configured proxy is dead); 4 attempts with 1s/2s/4s backoff rotating proxy→direct; patient budgets (30 s dial/TLS, 3-min per-attempt deadline under the unchanged 10-minute total); resume — a retry continues from where the download stopped (`.part` + `.part.meta` guard; stale parts from another version are never mixed, a complete part behind a blocked rename finishes without re-downloading).
- The update **check** got the same proxy awareness; the two failure messages now mention the VPN/proxy path and the release-page fallback.
- Tests: Go 8 new + 2 updated, all green locally on linux AND under `GOOS=windows go vet ./...` + the production build cross-compiled (Go 1.27.4 installed in the sandbox this session); frontend untouched — 145/145 green, tsc, token lint, AA contrast all pass.
- Version 1.12.1 (five places: `app.go`, `clavis.nsi`, `winres/info.json` — `file_version` also fixed from a stale 1.6.0.0, `types.ts`, tag).
