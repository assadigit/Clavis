# DECISIONS.md — Clavis

One line each: what was unclear, what was chosen, why. (SPEC §0.2.)

## Platform & tooling

1. **Wails version** — pinned `github.com/wailsapp/wails/v3 v3.0.0-beta.33` (the newest beta at build time, read from the official Go module proxy, not from memory) + `@wailsio/runtime@3.0.0-beta.33` on the npm side so the JS runtime matches the Go backend exactly.
2. **Cross-compilation host** — this build machine is Linux, not Windows. Wails v3 on Windows is pure Go (WebView2 via registry + syscalls, no CGO), so `GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build` produces a real Windows binary from Linux. The fallback in SPEC §2 (Wails v2 + fyne tray) was NOT needed.
3. **Build tooling without the wails3 CLI** — the app is built with plain `go build` + hand-written resource tooling (`tools/icopack`, `tools/syso` mirroring the Wails build's winres usage). The wails3 CLI mainly scaffolds and generates bindings; the runtime supports `Call.ByName("main.Clavis.…")`, so generated bindings are unnecessary and one less moving part.
4. **Frontend stack** — the exact React components, `design-tokens.css` and CSS recipes from the verified reference implementation (web edition), built with Vite (two entries: `popup.html`, `manager.html`) + Tailwind v4 (only for the utility classes the components already use). No visual value was added — tokens only.

## Behavior choices where the spec allowed latitude

5. **Manager visibility at launch** — normal launch shows the Manager window (so the app has a face on first run); the `--hidden` flag (used by Start-with-Windows) starts tray-only. The spec fixed the hidden case but not the normal one.
6. **Autostart syncing** — the HKCU `Run` value is synced to the *Start with Windows* setting on every launch (not only first run), so the setting self-heals if other software removes the entry. Value name "Clavis", command `…\Clavis.exe --hidden` via Wails' built-in autostart manager.
7. **Shortcut-conflict reporting at startup** — if `RegisterHotKey` fails at launch, Go emits a `clavis:shortcut-conflict` event and the Manager shows a dismissible banner with the spec message; changing the shortcut later re-registers and rolls the setting back on failure, so a dead combo is never saved.
8. **Popup hide-on-focus-loss** — implemented with Wails' `HideOnFocusLost` (native) plus a `clavis:popup-shown/hidden` event pair so the palette resets (query cleared, selection on top) on every open, per §3.3b.
9. **Esc in the popup** — handled in JS (back one level first, hide only at top level), so Wails' `HideOnEscape` is NOT used (it would hide the window on every Esc).
10. **Popup window sizing** — the webview reports its panel size (`ResizeObserver`, 640 px + 2×32 px shadow pad) and Go applies it in DIPs, so the window grows/shrinks with the rows and stays DPI-correct on any monitor.
11. **Alt-Tab suppression** — popup window uses `HiddenOnTaskbar` + `WS_EX_TOOLWINDOW` (`ExStyle 0x80`).
12. **Tray icon variants** — Wails' Windows tray does not support separate light/dark icons, so one icon ships: the primary-blue key with a contrasting outline, legible on both light and dark taskbars.
13. **Manager maximized look** — the Manager is a transparent frameless window that draws its own rounded glass frame with the token shadow pad; when maximized it goes edge-to-edge (detected by window-size heuristic).
14. **Manager geometry persistence** — bounds are saved when hiding/closing/minimizing/ quitting (never while maximized, so the last normal bounds survive).
15. **Browser-reserved shortcut rejection kept** — combos like Ctrl+T / Ctrl+W stay rejected in the capture UI even though Windows would accept them globally: owning them system-wide would break normal browser usage.
16. **Second instance** — Wails' `SingleInstance` (unique id + no encryption key needed on a local mutex); the second launch signals the first to open the Manager and exits, per §3.1.
17. **"Import backup" JSON** — read via the standard file input inside the webview (works natively in WebView2); folder import goes through a native folder picker in Go. Both feed the same conflict-resolution flow.

## Divergences fixed relative to the reference (web) implementation

18. **Daily-backup "today" check off-by-one** — the reference used `slice(0, 19)` of `clavis-data-YYYYMMDD-…`, which matches a 10-day window of dates sharing 7 date digits; the Go edition uses the full 20-char day prefix (verified by test: one daily backup per calendar day, newest 10 kept).
19. **Tiered search comparator crash** — the reference's `compareRanked` passed `Tiered` objects into `compareEntries` (a latent crash whenever two results shared a rank tier in a word query). Fixed to `a.entry`/`b.entry` in the desktop frontend; the web edition in the sandbox preview has the same fix queued.
20. **Corrupt-file recovery order** — recovery walks backups newest-first (the spec's "newest valid backup"); a naive oldest-first reading was caught and fixed by a test before release.
21. **Empty `categoryId: ""`** — treated as "no category" (null) rather than storing an empty string, keeping the file format clean.
22. **`slice` of `ManagerBounds` on empty settings** — a hand-edited empty shortcut string now falls back to the default instead of persisting "".

## Honest limits of this build host (no Windows available)

23. **Runtime behaviors that compile but could not be executed here**: OS-global hotkey while another app has focus, tray clicks, native clipboard-history exclusion formats, single-instance mutex, autostart registry value, WebView2 window rendering, installer flows. All are implemented through Wails v3's supported APIs (RegisterHotKey/Shell_NotifyIcon/SetClipboardData/registry, per the beta.33 source) and the pure-Go core under them is fully tested; the popup-open ≤150 ms budget is met by design (pre-created window + pre-loaded webview, measured 26.3 ms in the browser harness for the same UI) but could not be re-measured on real Windows hardware.
24. **Verification substitute** — the exact Go backend (store/dispatcher) + exact frontend were verified end-to-end in a real browser via Wails' official `-tags server` mode (headless HTTP+WebSocket runtime): UI → `Call.ByName` → Go store → `clavis-data.json` on disk → back to the UI, including item creation, category default-secret, masked previews, fuzzy search, copy side-effects, settings persistence, and the recovery/read-only behaviors covered by the Go test suite (68 tests, race-clean).
25. **WebView2 runtime in the installer** — checked via the EdgeUpdate ClientState registry keys (machine + user); when missing, Microsoft's official bootstrapper (embedded, 1.8 MB) runs per-user. It downloads from Microsoft only in that rare case — Clavis itself never goes online at runtime.

## v1.0.1 additions

26. **CSS cascade policy** — every Clavis component recipe now lives in `@layer components`, below Tailwind's utilities layer. The v1.0.0 recipes were unlayered, so `.clavis-btn{display:inline-flex}` silently beat the layered `md:hidden` utility on the mobile-nav button — the button could never be hidden on desktop (user report #1). Rule going forward: custom recipes never outrank a utility on the same element.
27. **Manager minimum width 800 DIP** (was 760): the three-column layout switches at 48rem (768px); a 760px window could slip below it and hide the sidebar entirely on a desktop app. 800 keeps the desktop layout guaranteed with margin.
28. **Menu surface opacity** — dropdown/context menus paint `color-mix(in srgb, var(--solid-surface-raised) 96%, transparent)` instead of `--glass-bg` (10% white): a floating menu over dense rows needs an (almost) opaque surface or the text underneath reads as a collision (user report #4). Where `color-mix` is unsupported the plain raised token is used. The outer panels' glass recipe is untouched.
29. **Desktop empty states** — on a completely empty store the detail column now orients the new user ("Welcome to Clavis" + the actual shortcut, rendered as a keycap) instead of repeating the list column's CTA; once entries exist, "Nothing selected" is a calm hint + New buttons (user report #2). The web edition (sandbox preview) received the same states.
30. **`--clavis-modal-vh`** — desktop windows are inset by the shadow pad, so modals size to `calc(100dvh - 2×pad)` via this root variable; the web edition keeps the `100dvh` fallback (variable undefined there).

## v1.0.2 additions

31. **Solid dark windows (the "gray background" fix)** — user report: opening Clavis from the taskbar showed a weird gray background around the app (a screenshot also showed the popup with a ~32px gray frame). Root cause: both windows relied on `BackgroundTypeTransparent` + a 32px transparent shadow pad around the painted panel; on that Windows 10 machine the WebView2/Win32 layer rendered the unpainted margin as the default gray (window brush / WebView2 fallback) instead of desktop translucency. Decision: stop relying on OS translucency entirely — popup and manager windows are now `BackgroundTypeSolid` with the token backdrop base `#0B1630`, and the pages paint edge-to-edge with no pad (`--clavis-modal-vh: 100dvh`; popup window == panel size exactly). The app keeps its glass look by blurring its own self-drawn backdrop, which works identically on every Windows 10 machine and also removes any first-show gray flash (Windows paints the dark brush before the webview renders).
32. **Row-level instant copy + pin toggle** — every list row (manager, both editions; popup rows gain a copy affordance icon) now carries a clipboard button (value for items; the whole `KEY=value` block for groups, same bytes as Ctrl+Enter in the popup) and a real pin switch (`updateItem`/`updateGroup` patch, pinned entries keep showing first per §5.1). Buttons sit in the row's trailing cluster, quiet at 55% opacity until hover/selection/copy so rows stay scannable; a ✓ replaces the copy icon for ~1.4 s after a successful clipboard write.
33. **Group credentials for a whole project (createGroupFromEnv)** — new action in both backends: create a group AND all its member items in one shot from pasted `KEY=value` lines (dotenv parsing, `DedupeKeys` so the group block round-trips; each item `isSecret: true` — never under-mask — name = key). The create-group form replaces the old "save first, then add items" dead end with a paste box + live parse preview (key chips, skipped-line warning) and a dynamic "Create group + N credentials" button; the "+ New" menu now labels its two choices ("One key, prompt or note" / "All credentials for a project (.env)").

## v1.0.3 additions

34. **Self-update from GitHub (user-requested exception to the offline rule)** — SPEC §2 said "no update checks", but the user explicitly asked for in-app updates ("with newer release in GitHub the app automatically uses newer portable or installed version without changing in data"). The compromise, documented here: the updater is strictly **pull-only** (two GETs: api.github.com `releases/latest`, with the public `releases.atom` feed as fallback when the API is rate-limited; then one GET of the chosen artifact) with a fixed, audited URL — no telemetry, no data ever leaves the machine, and checks only happen on demand or once per 12 h in the background. The GitHub repo had to become **public** for anonymous downloads to work (was private; the change is reversible). Mode detection: `HKCU\Software\Clavis\InstallDir` (written by NSIS) matching the running exe's folder ⇒ installed, else portable. **Installed** edition: download `Clavis-Setup-<ver>.exe` to %TEMP%, then a detached `cmd /c .clavis-update.cmd` waits for Clavis to exit, runs the setup with `/S` (NSIS silent per-user), relaunches. **Portable** edition: download `Clavis-Portable-<ver>.exe` as `Clavis.exe.new`, the script parks the old exe as `Clavis.exe.old`, moves the new one into place, relaunches, and the next launch deletes the `.old`. In both paths the data folder `%APPDATA%\Clavis` is never touched — the update swaps ONLY the program. Downloads are size-verified against the release manifest and land via a `.part` file that is atomically renamed; a mismatch is deleted and reported, never half-installed. UI: Settings → About gains a "Check for updates" button, an "Update to <ver>" primary button (with a progress bar driven by Go → JS events), release-notes preview, and a Release page link; the tray menu gains "Check for updates…"; the Manager shows a toast when the background check finds something. Non-Windows/dev-server builds honestly report "not installable here" and fall back to download buttons instead of pretending.

## v1.1.0 additions

35. **Full redesign to the Bitwarden design system (user-directed)** — the user rejected the original dark-glass aesthetic ("Follow bitwarden design system and follow it, i dont like this ui"), which supersedes SPEC §7's white+blue dark-glass art direction. The token layer was rebuilt from Bitwarden's own published values (`bitwarden/clients` → `libs/components/src/tw-theme.css`): brand blue `#175DDC` (hover `#1A41AC`), canvas `#F3F6F9` (background-alt), white surfaces with 1px `#D5DDE8` borders, text `#1B2029` / muted `#606D91`, status `#0C8018` / `#CB263A` / `#8E4000`, Bitwarden's blue-tint hover `rgba(26,65,172,.08)` and primary-100 selected-row tint `#DBE5F6`. Inter stays (Bitwarden's own UI font). Structural changes: flat full-bleed columns divided by 1px borders (replacing floating glass panels), hairline dividers between list rows, bordered icon tiles on rows/detail headers (`.clavis-icon-tile`), square column corners, white menus/modals/toasts with soft shadows, focus rings `rgba(23,93,220,.25)`. The old "Solid mode" toggle is repurposed as **Dark mode** using Bitwarden's dark tokens (`#121A27`/`#202733` surfaces, `#65ABFF` primary, dark text `#F3F6F9`); `osTransparency === false` no longer forces it because the flat theme needs no OS translucency. The glass-intensity slider is gone (meaningless without glass); `glassIntensity` stays in the data model for backward compatibility. Both windows switched from dark `#0B1630` to light backgrounds (popup `#FFFFFF`, manager `#F3F6F9`). No behavior, data-format, or shortcut changes — purely visual; all 80 Go tests and the byte-exact round-trip suite are untouched and green.

## v1.1.1 additions

36. **Popup "Recent" list + Open Clavis + two real input fixes (user-reported)** — the user asked for "10 recent used/copied passwords or groups password" in the popup, a clear button to reach the main app, and reported that the search bar "doesn't input and doesn't search". The search report turned out to be two genuine bugs: (a) **desktop zombie state** — the desktop keeps the popup component mounted while its window is hidden, and after a successful copy the `copied` state (which makes `onKeyDown` `preventDefault` everything) was never cleared, so the next show had a dead search box and a stuck "✓ Copied" banner (exactly what the user's screenshot showed); fixed by mounting the palette only while the window is open (state dies with the unmount) plus a self-clearing copy timeout. (b) **web-side comparator crash** — `compareRanked` in the web edition passed `Tiered` objects to `compareEntries`, so any query matching ≥2 same-tier entries crashed the render; fixed (the desktop copy already had the fix). Additionally the desktop popup could show without receiving keystrokes at all, because Wails' `Focus()` is a bare `SetForegroundWindow`, which Windows silently denies when Clavis isn't the foreground process (the classic tray-click case); `showPopup` now force-foregrounds via the `AttachThreadInput` recipe (same as PowerToys Run). Feature side (SPEC §5.1 amended): empty-query popup shows **Recent** — the 10 most recently used/copied entries, items AND groups (copying a whole group counts), most recent first — topped up with a **Pinned & frequent** section so the palette always offers 10 rows; section headers are presentation-only, selection stays a flat list. The Manager sidebar gains a matching **Recent** view. The popup footer gains an **Open Clavis** button (closes the popup, shows the Manager; wired through `platform.showManager()` on desktop). Popup list max-height grows from 8 to 10 rows; the web edition caps by viewport so search + footer always stay on screen, the desktop window keeps auto-sizing to its natural 10-row budget. No data-format changes — recency data (`lastUsedAt`, `useCount`) was already tracked by every copy on both editions.


## v1.1.2 additions

37. **Editor action-bar reorganization (user-reported layout feedback)** — the user flagged organization/alignment problems in the item editor's lower section ("the meta tip can move some where"; screenshot showed the "Enter saves · Ctrl+Enter adds a line" helper text floating mid-action-bar, a red Delete button crammed alongside Copy/Duplicate/⋯, and wrapping chaos on narrow panes). Fix, applied to both editors for consistency: (a) the keyboard hint moved to where the typing happens — a `FieldHint` directly under the Value textarea (new tiny ui-bits primitive, also replacing the ad-hoc `<p>` hints in the group editor's paste panel); (b) the footer became a real anchored action bar — hairline top border, `Save`/`Cancel` left, utility buttons right, so the layout reads as two intentional groups instead of one ragged wrap row; (c) **Delete item** moved into the ⋯ menu below a divider as a danger `MenuItem`, matching the group editor's pre-existing pattern (deleting a credential is rare, and for shared items the confirm modal still guards it; the extra click is safety, not friction); (d) Secret/Pinned toggles sit in `repeat(auto-fit, minmax(170px, 1fr))` equal-width columns that stack on narrow panes. SPEC §5.4 rewritten to describe the new bar; no behavior, shortcut, or data changes.
